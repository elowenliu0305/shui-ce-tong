# Feature Specification: 生产数据与 AI Agent

**Feature Branch**: `002-production-data-agent`

**Created**: 2026-10-17

**Status**: Draft

**Input**: 在已验收的 React 前端与服务契约基础上，接入真实邮箱账号、多企业数据、资料库全量入库、可追溯规则报告和带 RAG 引用的通用 AI Agent。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 使用真实账号与企业数据 (Priority: P1)

用户可以通过邮箱与密码注册、验证邮箱、登录和重置密码。登录后，用户可以创建、编辑、切换和删除自己的企业，并在不同设备上恢复当前企业及已保存数据。

**Why this priority**: 真实身份、持久化和企业隔离是后续体检、报告、会话与文件的共同前提。

**Independent Test**: 新用户完成注册、邮箱验证和建企，退出后再次登录，仍能看到原企业和上次保存的资料；另一账号无法读取该企业。

**Acceptance Scenarios**:

1. **Given** 未注册邮箱，**When** 用户提交有效邮箱和符合要求的密码，**Then** 系统创建待验证账号并发出验证邮件。
2. **Given** 已验证账号，**When** 用户登录并创建企业，**Then** 企业和当前企业选择被持久保存。
3. **Given** 用户拥有多家企业，**When** 切换当前企业，**Then** 画像、草稿、报告、会话和文件记录随企业一起切换且不串档。
4. **Given** 用户确认永久删除企业，**When** 删除成功，**Then** 该企业业务资产被级联删除，账号收藏仍保留，并返回可核对的删除摘要。

---

### User Story 2 - 生成可追溯且不可变的体检报告 (Priority: P1)

用户完善企业经营资料和 10 道风险题后，系统按已确认规则生成风险、政策匹配、节税测算与行动建议。每次完成体检都形成独立的时间快照。

**Why this priority**: 这是产品的核心价值，并且税务结论必须可复现、可审计、不随当前数据漂移。

**Independent Test**: 对同一企业连续完成两次不同输入的体检，两份报告结果可解释地不同，第一份报告保持原值。

**Acceptance Scenarios**:

1. **Given** 10 道题已全部回答，**When** 用户完成体检，**Then** 风险等级只由题目答案计算，企业资料只用于政策匹配与金额估算。
2. **Given** 某项政策条件资料缺失，**When** 生成报告，**Then** 政策标记为待确认并列出待补字段，不输出确定节税金额。
3. **Given** 某项政策已失效、未核验或明确不符合，**When** 生成新报告，**Then** 它不作为可享政策或金额依据展示。
4. **Given** 报告已生成，**When** 用户修改画像或系统更新政策规则，**Then** 旧报告的输入、结果、引用和版本保持不变。

---

### User Story 3 - 检索完整且可核验的资料库 (Priority: P1)

用户可以在首页和资料库中搜索全部政策、时讯、案例和其他资料，查看正文、文号、发布机构、效力、来源和原文件。所有原始来源都被保留，而只有结构化并核验通过的政策才参与匹配。

**Why this priority**: 资料库同时是用户搜索产品和税务 RAG 的证据底座，完整性与可追溯性必须先于 AI 回答。

**Independent Test**: 导入给定资料包后，清单中每个原始文件均有来源记录；已解析资料可按标题、文号、机构和正文命中；解析失败资料仍可下载原文件。

**Acceptance Scenarios**:

1. **Given** 一份包含重复、失效和解析失败文件的资料包，**When** 导入完成，**Then** 每个原始文件都有清单记录，重复关系与解析状态被明确标记而非静默丢弃。
2. **Given** 已解析资料，**When** 用户输入标题、文号、机构或正文关键词，**Then** 系统返回相关资料并显示当前效力状态。
3. **Given** 某政策已被新版取代，**When** 用户查看旧政策，**Then** 页面明确显示版本关系和新版入口。
4. **Given** 资料未完成核验，**When** 规则匹配或 AI 税务问答执行，**Then** 该资料不得被当作已确认的政策结论。

---

### User Story 4 - 获得带来源的通用 AI 协助 (Priority: P1)

用户可以向 AI Agent 询问税务、政策、企业报告以及非税收问题。税务和政策问题必须先检索资料库并附可点击来源；没有可靠依据时不得给出确定结论。其他问题可正常回答，并在相关时引导用户关注小微企业现金流、融资、成本与经营。

**Why this priority**: 这是产品的持续服务入口，同时税务高风险场景需要严格的证据和隔离边界。

**Independent Test**: 分别提交普通问题、有依据的税务问题、无依据的税务问题、当前企业报告问题和现金流问题，核对路由、引用、隔离、边界提示和建议追问。

**Acceptance Scenarios**:

1. **Given** 用户询问税务或政策问题，**When** 资料库有可靠依据，**Then** 回答包含资料标题、文号或发布机构、定位信息和可打开的来源。
2. **Given** 用户询问税务或政策问题，**When** 未检索到可靠依据，**Then** 回答明确说明依据不足，不输出确定性税务结论。
3. **Given** 用户询问普通非税收问题，**When** 不需要资料检索，**Then** 系统可直接回答且不伪造引用。
4. **Given** 问题需要企业或报告上下文，**When** Agent 生成回答，**Then** 只使用当前账号和企业授权范围内的最小必要数据。
5. **Given** 用户切换企业，**When** 打开历史会话或继续追问，**Then** 不得读取或引用另一企业的会话与报告。

---

### User Story 5 - 管理用户文件与分析记录 (Priority: P2)

用户可以为当前企业上传支持的文件、选择分析任务、查看处理状态和结果，并删除文件及相关分析记录。文件和结果始终按企业隔离。

**Why this priority**: 文件是未来企业资料补全与私有检索的输入，但不阻塞账号、体检、资料库和 Agent 的首批上线。

**Independent Test**: 在两家企业下分别上传文件并建立任务，确认列表互不可见；删除其中一份文件后，原文件与派生记录不再可访问。

**Acceptance Scenarios**:

1. **Given** 用户选择受支持文件，**When** 上传完成，**Then** 文件只属于当前企业，并显示名称、类型、大小、时间和处理状态。
2. **Given** 文件处理失败，**When** 用户查看结果，**Then** 页面区分未读取、部分读取和处理失败，不生成未验证的事实。
3. **Given** 用户确认删除文件，**When** 删除成功，**Then** 原文件、派生文本、向量和分析记录一并删除。

### Edge Cases

- 注册邮件延迟、过期、重复点击或账号已存在时，界面必须给出可继续的状态而不暴露账号细节。
- 会话过期、企业已删除或用户撤销请求时，任何后续读写都必须失败且不泄露资源是否存在。
- 同一用户在多端同时修改草稿时，系统不得静默覆盖较新版本。
- 体检提交重复、网络超时或部分处理失败时，不得创建两份相同报告，也不得展示部分完成的结论。
- 政策在查询日期过期、废止、部分有效或版本链不完整时，系统必须降级为待确认或不参与匹配。
- 导入资料是密码文件、空文件、不支持格式、超大文件或正文为扫描图时，原文件记录仍被保留并标注处理状态。
- 重复资料的原文件与正规化正文哈希不一致时，系统保留原始来源并标记疑似重复，不自动合并为已核验资料。
- 搜索和 RAG 同时找到冲突或不同版本的依据时，回答必须标注冲突，优先展示当前有效且已核验来源。
- 模型、检索、文件或规则服务不可用时，用户能区分失败阶段并安全重试，已成功的历史资产不受影响。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持邮箱与密码注册、邮箱验证、登录、退出和密码重置，且任何可读数据中不得出现明文密码或验证凭据。
- **FR-002**: 系统 MUST 将企业、画像草稿、问卷草稿、体检、报告、会话和文件数据限制在所属账号与企业范围内。
- **FR-003**: 系统 MUST 支持一个账号管理多家企业，并持久保存当前企业选择。
- **FR-004**: 系统 MUST 在企业删除前要求明确确认，并原子性删除企业业务资产、保留账号收藏、返回删除摘要。
- **FR-005**: 系统 MUST 为企业画像和 10 道风险题维护独立草稿，支持自动保存、恢复、未知值与并发冲突检测。
- **FR-006**: 系统 MUST 保证风险等级仅由 10 道题决定：安全答案计 0，异常答案计 1，不清楚计 0 且生成待核验项；0–2、3–5、6–10 分别是低、中、高风险。
- **FR-007**: 系统 MUST 保证健康度等于 `(10 - 已确认风险数) × 10%`，且同一输入在同一规则版本下产生相同结果。
- **FR-008**: 系统 MUST 使用企业地区、行业、营收、研发投入等画像字段筛选政策和估算节税金额，不得将其混入风险评分。
- **FR-009**: 系统 MUST 在资格、必需输入和可展示公式全部完整时才输出数值金额，并排除互斥或重叠项目的重复累加。
- **FR-010**: 系统 MUST 对每次完成体检创建不可变时间快照，包含当次输入、结果、规则版本、资料版本、引用和时间。
- **FR-011**: 系统 MUST 拒绝对已完成体检和报告的覆盖更新；更正或重新体检必须创建新记录。
- **FR-012**: 系统 MUST 对体检提交进行去重，使网络重试不会创建重复报告。
- **FR-013**: 系统 MUST 为资料包中每个原始文件保留来源、存储引用、文件哈希、解析状态、重复关系与审核状态。
- **FR-014**: 系统 MUST 将可读正文组织为可搜索资料，保留标题、文号、机构、日期、效力、类别、地区、行业、版本关系和原文定位。
- **FR-015**: 系统 MUST 支持标题、文号、机构、元数据和正文检索，并在没有结果时返回明确空状态。
- **FR-016**: 系统 MUST 保留解析失败资料的原文件下载能力，且不得伪造正文。
- **FR-017**: 系统 MUST 只允许完成结构化并核验通过的当前有效政策参与企业匹配、风险依据和金额计算。
- **FR-018**: 系统 MUST 支持账号级收藏，并在用户切换企业时重新计算收藏资料的当前企业适用性。
- **FR-019**: AI Agent MUST 将普通问题、税务/政策/案例问题、企业/报告问题和小微企业金融经营问题区分处理。
- **FR-020**: AI Agent MUST 在回答税务、政策或案例问题前执行资料检索，并在有可靠依据时返回可点击、可定位、可核验的引用。
- **FR-021**: AI Agent MUST 在未检索到可靠依据时返回“依据不足”状态，不得生成确定性税务结论或伪造引用。
- **FR-022**: AI Agent MUST 在普通问题不需要资料检索时允许直接回答，并在相关时提供现金流、融资、成本、预算和经营建议的自然引导。
- **FR-023**: AI Agent MUST 在使用企业上下文前验证归属关系，只传递回答所必需的脱敏字段，排除邮箱、企业名称、统一社会信用代码和无关完整文件。
- **FR-024**: 系统 MUST 按企业保存会话和消息，并在企业切换、删除或会话过期后阻止跨范围读写。
- **FR-025**: 系统 MUST 将模型失败、检索失败、规则失败和文件处理失败作为可区分状态返回，不得将错误伪装为成功回答或报告。
- **FR-026**: 系统 MUST 使模型、检索和其他特权凭据只在受控服务环境中可用，不得进入浏览器代码、用户数据或版本库。
- **FR-027**: 系统 MUST 记录影响结论、数据删除、资料审核和 AI 工具调用的可审计事件，同时避免在日志中写入密码、密钥、完整企业私密资料或完整文件正文。
- **FR-028**: 系统 MUST 支持为当前企业上传受支持文件，并保存文件元数据、处理状态与分析记录。
- **FR-029**: 系统 MUST 在用户确认删除文件后，删除原文件及其派生文本、索引和分析记录，且删除后不得再被检索或模型使用。
- **FR-030**: 系统 MUST 为所有对用户可见的规则、资料、报告和 AI 引用保留稳定标识和版本信息。

### Key Entities

- **Account**: 已验证用户身份，拥有企业、账号收藏和个人偏好。
- **Enterprise**: 账号管理的单家企业，是画像、问卷、报告、会话和文件的隔离边界。
- **Company Profile Draft**: 企业经营资料的可版本化草稿，显式区分已知、不清楚和未填写。
- **Risk Questionnaire Draft**: 10 道风险题的当前答案草稿。
- **Assessment Run**: 一次可追溯的体检执行，引用当次输入、规则和资料版本。
- **Report Snapshot**: 与已完成体检一对一的不可变用户报告。
- **Knowledge Source**: 导入资料包中的单个原始文件及其哈希、存储、解析、重复与审核状态。
- **Knowledge Document**: 一份可搜索的规范资料，可关联一个或多个原始来源。
- **Knowledge Chunk**: 保留章节与原文定位的检索单元，用于语义检索与引用。
- **Policy Rule Version**: 经审核的政策结构化条件和计算公式版本。
- **Favorite**: 账号级的资料收藏，不随企业删除。
- **Agent Conversation / Message**: 按企业隔离的会话与消息，保留意图、状态、引用、工具摘要和建议追问。
- **Enterprise File / Analysis Record**: 用户上传的私有文件、处理状态和派生分析。
- **Audit Event**: 与数据更改、删除、规则、资料审核和 Agent 工具调用相关的脱敏审计记录。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 95% 的新用户能在 3 分钟内完成注册、邮箱验证和首家企业创建。
- **SC-002**: 账号 A 对账号 B 的企业业务数据读写成功率为 0%，自动化隔离测试覆盖所有企业级资产。
- **SC-003**: 已保存草稿在刷新、重新登录和设备切换后的可恢复率达到 99.9%，且并发更新不静默覆盖新版本。
- **SC-004**: 对固定输入、日期、规则和资料版本，100% 的重复体检得到相同预览结果；网络重试不会产生重复最终报告。
- **SC-005**: 已生成报告在画像、规则或政策后续变更后的快照一致性为 100%。
- **SC-006**: 资料包每个原始文件均产生一条可对账的来源记录，失败和重复项不丢失；导入数与源清单数一致。
- **SC-007**: 已解析资料对精确标题、文号、发布机构和代表性正文词的检索召回率达到 95% 以上，常见搜索的 95% 在 2 秒内出现首批结果。
- **SC-008**: 100% 的税务、政策和案例回答要么包含至少一个可打开且可定位的可靠引用，要么明确返回依据不足。
- **SC-009**: 普通非税收回答中的伪造政策引用率为 0%；企业或报告问答中的跨企业上下文泄露率为 0%。
- **SC-010**: 企业或文件删除成功后，其业务记录、派生内容和检索索引在系统对用户报告成功时已全部不可访问，收藏保留规则符合率为 100%。
- **SC-011**: 浏览器代码、用户可读数据、版本库和用户可见错误中出现明文密码、验证凭据或特权密钥的次数为 0。
- **SC-012**: 在 360–430px 宽度下，真实账号、体检、搜索、Agent 和文件主链路均无横向溢出、底部遮挡或无法键盘访问的主要操作。

## Assumptions

- 第一版每个企业只归一个账号管理，不包含企业成员邀请、角色和多人协作。
- 账号入口固定为邮箱与密码，不在本阶段增加手机验证码、单点登录或第三方社交登录。
- 当前 React 页面、领域规则和服务契约是交互与业务基线，真实数据接入不改变已确认的用户链路。
- 资料包内容已获得用于本产品存储、检索、展示和生成引用的授权。
- 重复与版本关系可先由导入程序标记，进入规则匹配前必须完成人工核验；本阶段不建设完整管理后台。
- AI 模型服务凭据由产品负责人在对接阶段提供，在此之前可使用实例数据与可替换的本地配置验证除真实生成之外的完整链路。
- 税务、政策、融资、投资、法律和医疗回答均属信息辅助，不替代税务机关口径或专业意见。
- 高风险数据和密钥使用服务端安全默认：最小权限、脱敏日志、加密传输、隔离存储和可审计操作。

## Out of Scope

- 多人企业成员、组织角色、邀请和审批流。
- 直接代理纳税申报、开票、缴款、信贷审批或投资交易。
- 未经核验的自动政策规则发布。
- 完整的内部资料审核后台；首版只需要可审计的导入和核验状态。
- 训练、微调或自主托管大模型；本阶段使用可替换的外部模型能力。
