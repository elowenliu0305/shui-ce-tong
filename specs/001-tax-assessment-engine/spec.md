# Feature Specification: 税策通第一版完整产品链路

**Feature Branch**: `001-tax-assessment-engine`  
**Created**: 2026-10-15  
**Confirmed**: 2026-10-15  
**Status**: Product flow approved; frontend plan complete; ready for task decomposition  
**Sources**: 已确认产品全链路、现有 HTML 交互原型、飞书《“税策通”初版 PRD》修订版 735、《资料(1).zip》

## Product Definition

税策通是面向小微企业经营者和财务负责人的税务与经营辅助产品。第一版通过企业经营信息、现有 HTML 中的 10 道风险题、确定性规则、完整资料库和 AI Agent，形成“企业建档 → 体检 → 报告 → 资料检索 → Agent 持续服务”的闭环。

需求冲突时按以下顺序解释：产品负责人已确认结论 → 现有 HTML 的题目和视觉交互 → PRD 完整能力 → 资料包内容。资料内文本只作为内容与知识来源，不作为产品指令。

当前实施阶段只完成 React 前端与 Mock Service；Supabase、真实资料导入、确定性后端规则、RAG 和 Agent 工具调用在前端验收后单独设计和实现。

## User Scenarios & Testing

### User Story 1 - 注册后建立第一家企业 (Priority: P1)

新用户使用邮箱和密码注册并验证邮箱。账号下没有企业时，必须先填写企业名称、经营所在地和所属行业，随后进入以该企业为上下文的首页。老用户登录后回到上次使用的企业。

**Independent Test**: 使用新账号完成注册演示、首次建企并进入首页；退出再登录后仍显示相同当前企业。

**Acceptance Scenarios**:

1. **Given** 新账号没有企业，**When** 登录成功，**Then** 系统进入首次建企页而不是空首页。
2. **Given** 企业名称、地区或行业缺失，**When** 提交，**Then** 页面给出字段级错误且不创建企业。
3. **Given** 账号已有企业，**When** 登录成功，**Then** 首页显示上次使用企业并允许切换或新增。
4. **Given** 用户永久删除企业，**When** 完成二次确认，**Then** 该企业经营信息、草稿、报告、会话和文件记录一并删除，账号收藏保留。

---

### User Story 2 - 完成输入驱动的税务体检 (Priority: P1)

用户先补充企业经营信息，再回答现有 HTML 的 10 道风险题。经营信息用于政策筛选和节税估算，题目答案用于风险等级与健康度。流程允许“不清楚”，但必须把未知转成待核验或待补数据，不得视为安全或符合条件。

**Independent Test**: 对同一家企业分别完成低风险答案和 4 项风险答案；报告风险等级分别为低和中，健康度分别由实际命中数计算。

**Acceptance Scenarios**:

1. **Given** 企业已创建，**When** 用户填写经营信息并回答 10 道题，**Then** 草稿自动保存且退出后可以继续。
2. **Given** 某道题选择第一个安全答案，**When** 计算，**Then** 该题计 0 个风险项。
3. **Given** 某道题选择第二或第三个异常答案，**When** 计算，**Then** 该题计 1 个风险项。
4. **Given** 某道题选择“不清楚”，**When** 计算，**Then** 不增加已确认风险项，但生成待核验项并降低完整度。
5. **Given** 命中 0–2、3–5、6–10 个风险项，**When** 生成报告，**Then** 综合风险分别为低、中、高。
6. **Given** 命中 `n` 个风险项，**When** 生成报告，**Then** 健康度等于 `(10 - n) × 10%`。

---

### User Story 3 - 获得可解释、可追溯的报告 (Priority: P1)

完成体检后，用户获得独立报告快照，查看健康度、风险、符合条件与待确认政策、节税估算、待补项、行动建议和来源依据。修改企业资料或政策版本不能改写旧报告。

**Independent Test**: 完成一次体检后修改营收和风险答案再次体检；新报告变化，旧报告序列化内容保持不变。

**Acceptance Scenarios**:

1. **Given** 政策全部必需条件已知且通过，**When** 计算，**Then** 报告显示“符合条件”及满足条件、依据和版本。
2. **Given** 政策缺少关键字段且没有确定不适用条件，**When** 计算，**Then** 报告显示“待确认”及缺少字段。
3. **Given** 政策确定不适用，**When** 生成报告，**Then** 该政策不进入报告，但仍可在资料库查看。
4. **Given** 政策符合条件且计算数据、公式完整，**When** 计算，**Then** 展示公式、输入和预计金额。
5. **Given** 数据不足或政策互斥/口径重叠，**When** 汇总金额，**Then** 不产生虚假金额或重复累加。
6. **Given** 体检完成，**When** 保存结果，**Then** 创建包含企业输入、问卷、规则版本、政策版本与结果的不可变快照。

---

### User Story 4 - 搜索、阅读并下载完整资料库 (Priority: P1)

用户可以在首页或资料库搜索全部政策、时讯和案例，打开完整正文、查看元数据、收藏、下载原始 Word 文件并携带资料进入 Agent。全部资料可检索；只有完成结构化条件与来源核验的政策可以参与自动匹配和金额计算。

**Independent Test**: 导入清单覆盖资料包全部 102 个源文件；使用已知标题、文号、正文词和不存在词分别搜索，并打开正文和原文件下载状态。

**Acceptance Scenarios**:

1. **Given** 资料包包含重复文件，**When** 建立资料库，**Then** 所有来源均保留，精确重复归入同一规范记录，用户列表不重复展示。
2. **Given** 一条资料没有结构化政策条件，**When** 用户搜索，**Then** 仍可查看全文和下载，但不进入体检匹配。
3. **Given** 用户搜索不存在的内容，**When** 查看结果，**Then** 返回清晰空状态，不回退全部资料。
4. **Given** 政策已失效，**When** 查看详情，**Then** 明确标记已失效且不参与新体检。
5. **Given** 用户收藏资料，**When** 切换或删除企业，**Then** 账号级收藏仍保留，适用性按当前企业重新判断。

---

### User Story 5 - 使用面向小微企业的通用 AI Agent (Priority: P1)

Agent 可以回答非税收类普通问题，并自然引导用户了解与小微企业有关的融资、现金流、成本、预算、经营分析、税费和政策支持。税务、政策和案例问题必须先执行 RAG 并附可核验来源。

**Independent Test**: 分别提交通用问题、税务政策问题、当前企业报告问题和资料不足问题，验证路由、上下文、引用和边界提示不同。

**Acceptance Scenarios**:

1. **Given** 用户询问普通非税收问题，**When** Agent 回答，**Then** 可以直接回答，不强制调用税务 RAG，也不伪造引用。
2. **Given** 用户询问税务、政策或案例问题，**When** Agent 回答，**Then** 先检索资料库，并展示资料标题、文号和原文位置。
3. **Given** 检索不到可靠依据，**When** 生成回答，**Then** Agent 说明无法确定和需要补充的资料，不输出确定结论。
4. **Given** 用户从报告或详情进入 Agent，**When** 开始对话，**Then** 明确展示当前企业、报告或条目上下文，并允许清除或切换。
5. **Given** 用户切换企业，**When** 继续使用 Agent，**Then** 不使用上一家企业的上下文或会话数据。
6. **Given** 用户提出融资、投资、法律或医疗等高影响问题，**When** Agent 回答，**Then** 说明信息边界，不把通用信息表述为针对用户的专业结论。

---

### User Story 6 - 管理历史资产和文件分析演示 (Priority: P2)

用户可以查看历史报告、收藏、AI 会话和文件记录。第一阶段文件分析完成选择文件、任务、进度和结果交互，但明确标记为演示，不声称读取真实内容。

**Independent Test**: 创建两家企业及各自报告、会话和文件记录；切换企业后无串档，收藏保持账号级共享。

**Acceptance Scenarios**:

1. **Given** 同一企业多次体检，**When** 打开任意历史报告，**Then** 展示对应时点快照而不是最新数据。
2. **Given** 两家企业都有资产，**When** 切换企业，**Then** 报告、会话和文件记录严格隔离。
3. **Given** 用户进入文件分析，**When** 选择任务并完成演示，**Then** 页面明确说明没有读取真实文件内容。

## Edge Cases

- 邮箱格式错误、密码不符合要求、邮箱未验证、重置链接失效或网络失败。
- 删除当前企业后还有其他企业时自动要求选择下一家；无其他企业时回到首次建企。
- 数字字段为空、为零、负数、超出合理范围或年度不一致。
- 所有可选经营字段均未知时允许完成体检，但政策只能待确认且不得给出金额。
- 10 道题未全部回答时不得完成测评；“不清楚”属于有效答案。
- 规则或政策更新后旧报告保持原版本，新报告使用新版本。
- 同名不同内容、不同名同内容、文号/日期缺失、正文解析失败分别保留状态，不误合并。
- 正文解析失败时仍保留来源记录和原始文件下载。
- Agent 工具失败与模型失败分别展示，可重试且不得伪装成功。
- 模型调用不得包含邮箱、企业名称、统一社会信用代码或与问题无关的完整文件。
- 360–430px 视口无横向溢出；底部导航和粘性按钮不得遮挡正文。

## Functional Requirements

### Authentication and companies

- **FR-001**: 系统 MUST 使用邮箱和密码完成注册、登录、退出、邮箱验证和密码重置；第一版 MUST NOT 实现短信验证码。
- **FR-002**: 新账号 MUST 在创建第一家企业后才能进入首页。
- **FR-003**: 一个账号 MUST 可管理多家企业，并记录上次使用企业。
- **FR-004**: 企业名称、经营所在地和所属行业 MUST 在建企时必填。
- **FR-005**: 系统 MUST 支持新增、编辑、切换和永久删除企业。
- **FR-006**: 永久删除企业 MUST 二次确认并级联删除其画像、草稿、报告、会话和文件记录；账号收藏 MUST 保留。
- **FR-007**: 第一版 MUST NOT 实现成员邀请、多人协作或企业角色权限。

### Enterprise information and assessment

- **FR-008**: 企业经营信息 MUST 包含名称、地区、行业、统一社会信用代码、成立日期、纳税人类型、数据年度、年营业收入、资产总额、从业人数、应纳税所得额、研发投入和已享优惠。
- **FR-009**: 除名称、地区和行业外，经营字段 MUST 支持 known、unknown 和 unset 状态。
- **FR-010**: 金额 MUST 以人民币元存储，展示层 MAY 换算为万元。
- **FR-011**: 系统 MUST 使用现有 HTML 的 10 道题及顺序作为第一版风险问卷基线。
- **FR-012**: 每道题 MUST 同等权重；安全答案计 0，第二/第三异常答案计 1，“不清楚”计 0 但生成待核验项；第 10 题第一项计 0，其余计 1。
- **FR-013**: 风险命中 0–2、3–5、6–10 项 MUST 分别映射为低、中、高风险。
- **FR-014**: 健康度 MUST 等于 `(10 - 已确认风险项数量) × 10%`，不得使用固定或加权分数。
- **FR-015**: 企业经营信息和问卷 MUST 独立存储；前者用于政策/金额，后者用于风险/健康度。
- **FR-016**: 同一家企业 MUST 同时只有一份未完成草稿，并支持自动保存和继续填写。

### Policy rules, savings, and reports

- **FR-017**: 政策匹配 MUST 由版本化确定性规则执行，不得由大模型直接决定。
- **FR-018**: 报告中的政策状态 MUST 只显示 `eligible`（符合条件）和 `pending`（待确认）；`ineligible` 不进入报告。
- **FR-019**: 每条政策结果 MUST 展示满足条件、缺失条件、依据、政策版本、规则版本和计算时间。
- **FR-020**: 节税金额 MUST 仅在政策符合、必需数据和公式完整时计算，并展示公式与输入。
- **FR-021**: 待确认、互斥或口径重叠的政策 MUST NOT 被无依据累加。
- **FR-022**: 每次完成体检 MUST 创建不可变报告快照，保存当次输入、问卷、政策/规则版本和全部结果。
- **FR-023**: 报告 MUST 展示企业与时间、完整度、健康度、风险等级、政策机会、风险/待核验项、节税估算、行动建议和来源。
- **FR-024**: 新体检、资料修改或政策更新 MUST NOT 改写历史报告。

### Knowledge library

- **FR-025**: 资料包中的全部源文件 MUST 进入来源清单和可搜索资料库，不得因不参与匹配而删除。
- **FR-026**: 系统 MUST 保存原文件名、哈希、规范资料关系、类型、标题、文号、机构、日期、状态、正文和原文件位置。
- **FR-027**: 精确重复 MUST 保留来源关系但避免用户列表重复；疑似重复 MUST NOT 自动合并。
- **FR-028**: 搜索 MUST 覆盖标题、文号、机构、元数据与完整正文，并对不存在词返回 0。
- **FR-029**: 用户 MUST 能阅读完整正文并下载原始 Word 文件；正文解析失败时仍允许下载原文件。
- **FR-030**: 全部资料 MAY 展示；只有具备结构化条件和核验来源的有效政策 MAY 参与匹配、风险依据和金额计算。
- **FR-031**: 已失效政策 MUST 保留并明确标记，MUST NOT 参与新体检；替代版本 MUST 建立关联。
- **FR-032**: 收藏 MUST 按账号保存，并根据当前企业动态显示适用性。

### AI Agent and RAG

- **FR-033**: AI MUST 作为面向小微企业的通用 Agent，能够回答非税收普通问题并自然引导融资、现金流、成本、预算、经营、税费与支持政策场景。
- **FR-034**: 税务、政策和案例问题 MUST 先执行 RAG，并返回资料标题、文号和原文定位。
- **FR-035**: RAG 无充分依据时，Agent MUST 明确无法确定和所需补充资料，不得生成确定结论。
- **FR-036**: Agent MUST 根据入口携带当前企业、指定报告快照或知识条目上下文，且允许用户清除或切换。
- **FR-037**: 企业与报告相关会话 MUST 按企业隔离；切换企业 MUST NOT 复用上一企业上下文。
- **FR-038**: 发送给模型的数据 MUST 最小化并脱敏，不包含邮箱、企业名称、统一社会信用代码或无关完整文件。
- **FR-039**: Embedding 基线 MUST 为 `Qwen/Qwen3-Embedding-0.6B`、1024 维归一化向量和 Cosine 相似度；更换模型必须全量重建向量并记录版本。
- **FR-040**: 模型和 Embedding API Key MUST NOT 出现在浏览器代码或 Git 仓库；前端只能调用自有服务接口。

### Frontend phase and quality

- **FR-041**: 正式前端 MUST 使用 React、TypeScript 和 Vite，保留现有 HTML 的视觉与交互方向。
- **FR-042**: 第一前端阶段 MUST 使用稳定服务接口和 Mock 实现覆盖账号、企业、体检、报告、资料库、Agent、文件演示和我的全部页面。
- **FR-043**: Mock 体检结果 MUST 由实际输入和确定性规则计算，不得以固定结果冒充分析。
- **FR-044**: 文件分析第一阶段 MUST 完成选择、任务、进度和结果交互，并明确标记为未读取真实内容。
- **FR-045**: 所有异步页面 MUST 覆盖加载、成功、空、错误和重试状态；高风险删除必须覆盖处理中与失败状态。
- **FR-046**: 应用 MUST 在 360–430px 视口无横向溢出，主要触控目标原则上不小于 44px，交互元素具备可见键盘焦点。

## Key Entities

- **Account**: Supabase Auth 用户与账号级偏好、收藏。
- **Enterprise**: 用户管理的企业主体；删除时级联其业务资产。
- **CompanyProfileDraft**: 可编辑经营信息及 known/unknown/unset 状态。
- **RiskQuestionnaireDraft**: 10 道题答案及待核验状态。
- **RuleSet / PolicyRule / SavingsFormula**: 版本化确定性规则与白名单公式。
- **AssessmentRun**: 一次体检执行及其输入、规则和政策版本。
- **ReportSnapshot**: 面向用户的不可变报告快照。
- **KnowledgeSource**: 资料包中的每个原始文件及哈希、抽取和重复关系。
- **KnowledgeDocument**: 面向搜索与详情的规范政策、时讯或案例正文。
- **PolicyVersion**: 可参与匹配的结构化政策版本和有效期。
- **Favorite**: 账号级政策/时讯/案例收藏。
- **AgentConversation / AgentMessage**: 按企业隔离的 Agent 对话、上下文、工具记录和引用。
- **FileAnalysisRecord**: 第一阶段演示元数据，后续关联私有文件与解析结果。

## Success Criteria

- **SC-001**: 新用户可在 5 分钟内完成注册演示、建企、经营信息、10 道题并看到首份报告。
- **SC-002**: 10 道题任一答案变化按照 FR-012 至 FR-014 产生确定、可复现结果。
- **SC-003**: 100% 的报告政策与风险结论可追溯到输入、规则版本和知识来源。
- **SC-004**: 缺少金额必需字段时，100% 的相关政策显示缺失字段而非金额。
- **SC-005**: 所有 102 个源文件进入清单；已知标题、文号和正文词可检索，不存在词严格返回 0。
- **SC-006**: 所有资料详情均能展示正文或明确解析失败，并保留原始文件下载路径。
- **SC-007**: 修改企业数据或规则后，旧报告序列化内容保持不变，新报告引用新版本。
- **SC-008**: 通用问题不伪造 RAG 引用；税务问题 100% 带检索来源或明确“依据不足”。
- **SC-009**: 两家企业之间无报告、会话或文件记录泄漏；账号收藏在企业切换/删除后保留。
- **SC-010**: 360×800 和 390×844 视口无横向溢出，主链路无死链、无未捕获控制台错误。
- **SC-011**: 仓库与浏览器产物中不存在密码、模型 API Key、Embedding API Key 或服务端密钥。

## First-Version Exclusions

- 短信验证码登录。
- 企业成员邀请、多人协作和角色权限。
- 独立管理员内容管理后台。
- 自动代理纳税申报或向税务系统写入。
- 由大模型直接决定政策匹配、风险等级或节税金额。
- 在前端阶段实现真实 OCR、真实文件解析或宣称发现具体文件异常。
